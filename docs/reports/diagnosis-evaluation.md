## 外部 Provider 适配

服务端集成测试用临时本机 HTTP 服务模拟外部端点，**按 URL 分派**而不是对任何路径返回同一形状——
否则测试无法证明适配层究竟走了哪条通道。四个用例覆盖：Responses API 正常返回、
端点拒绝结构化输出后降级到 chat/completions、非能力类错误（401）不触发降级、
无效 JSON 返回 502 且不影响 Issue 证据与健康检查。

### 真实端点实测（2026-08-31）

| 端点                     | 通道                  | 结果 |  延迟 | tokens in/out |
| ------------------------ | --------------------- | ---- | ----: | ------------- |
| DeepSeek `deepseek-chat` | Responses API         | 通过 | 8.7 s | 2315 / 1147   |
| DeepSeek `deepseek-chat` | chat/completions 降级 | 通过 | 8.1 s | 2252 / 971    |

降级路径通过一个本地代理验证：该代理对 `/responses` 返回 400、把 `/chat/completions`
转发给真实 DeepSeek，因此走的是真实模型而非 mock。两次结果都通过了共享 Zod Schema 校验
（含 `evidence[].source` 的枚举约束）。

**实测推翻了一个常见假设。** DeepSeek **支持** Responses API 的严格 json_schema，
却拒绝 `chat/completions` 的 `json_schema`（400 `This response_format type is unavailable now`）——
能力分布与「国产端点只有 chat/completions」的直觉相反。这正是适配层按端点能力探测、
而不是按厂商名字硬编码的理由。

以上验证的是适配契约与故障隔离，**不代表外部模型的语义质量**。

## 本评测能够证明

- 每条生成记录都符合共享 Zod Schema。
- 每个固定场景都会返回带标签的证据，以及多个具有置信度评分的假设。
- 提示词版本与脱敏上下文的组合哈希能够复用未变化的结果。

## 本评测无法证明

这套确定性的冒烟测试不衡量外部模型的语义质量、对人的实际帮助、召回率或幻觉情况。在声明这些
指标前，应增加 20–30 个独立标注的事故、人工评分标准、盲评、提供方/模型快照、重复试验、拒答
处理，以及延迟和 Token/成本采集。本仓库会如实说明这一限制，而不会虚构 AI 质量数据。
