# 阶段 09 — 查询、源码映射与调查体验完善

> **数字口径**：本文记录的是该阶段完成当时的测量值，仅作历史留档。
> 最新基线以 [`docs/reports/performance.md`](../reports/performance.md) 为唯一权威来源；
> 两者不一致时以报告为准。

## 阶段目标

修复统计、分页、Source Map 行列语义和 Web Vitals 样本偏差，并把服务端已经具备的数据能力真正
暴露到调查工作台，消除移动端溢出和“看似可操作、实际无行为”的控件。

## 实现步骤

1. 项目事件总数改为按 Release 归属统计全部事件，因此成功网络请求和性能样本不再被排除。
2. 对 Issue 页码、每页数量、事件数量和时间边界做有限整数归一化；查询服务内部再次限制事件
   数量，避免 `NaN` 导致 500 或 SQLite 的负 `LIMIT` 返回全部记录。
3. 修复 Issue 页分页按钮被通用筛选逻辑重置为第一页的问题，并完善 Release、浏览器、路由和
   时间窗口筛选；浏览器筛选区分 Edge、Chrome 和 Safari 的 User-Agent 重叠。
4. 将浏览器堆栈的 1 基列号转换为 Source Map Consumer 使用的 0 基列号，再把原始源码列号转回
   面向开发者的 1 基显示；测试使用非零列号，避免伪造的 `:1:0` 掩盖偏移。
5. Web Vitals 插件只在页面隐藏、离开或销毁时提交最终 LCP、累计 CLS 和最大 INP；FCP 与 TTFB
   保持单次上报。插件销毁顺序保证最终指标先入队、Transport 最后关闭并发送。
6. 性能 API 在总体 p50/p75/p95 之外返回按 Release、路由、浏览器的 p75 对比和 7 天日趋势；
   Dashboard 提供指标切换与对应视图。
7. Issue 详情页展示浏览器、路由和 Release 三类分布；“重新生成”显式发送 `force: true`，不再
   误命中诊断缓存。
8. 项目切换器改为真实可选控件，全局搜索按钮和 `⌘/Ctrl + K` 会进入 Issue 搜索框；Issue 长标题
   增加 `min-width: 0` 与任意位置换行，消除窄屏横向溢出。
9. 新增项目总事件、非法分页、真实性能分组、Web Vitals 最终采样和 Source Map 非零列映射测试。

## 验证方式

```bash
pnpm verify
pnpm test:e2e
```

浏览器人工验收覆盖项目总数 307、全局搜索聚焦、Release 筛选 URL、每页 1 条时翻到第 2/4 页、
性能指标切换、三类 Issue 分布，以及诊断强制重生成时间更新。移动端无溢出断言将在最终回归阶段
固定为自动化测试。
